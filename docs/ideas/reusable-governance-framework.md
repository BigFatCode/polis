# Reusable governance framework

**Status:** Parked; adjacent interest outside the current game goal.

## Motivation

The owner is interested in a democracy or collective-decision framework that could be applied beyond the game, even if the game itself does not succeed. Preserve this possible value without committing the project to a second product.

## Revisit when

- Defining the boundaries between governance rules and game mechanics.
- A concrete non-game decision-making use case becomes available.
- Game experiments reveal useful decision mechanisms worth evaluating independently.

## Possible design implications

When discussing domains, examine which concepts concern collective decisions and which concern the simulated world. Proposals, eligibility, voting, authority, and policies are candidates for the former; resources, progression, and victory conditions are candidates for the latter. A delivery interface such as Telegram or a browser is another consideration.

This is a lens for evaluating boundaries, not an accepted architecture. It does not prescribe packages, services, an extraction, a public API, or a generic rules engine. Separate contexts should follow concrete language and behavior requirements discovered during design.

## Questions if activated

- What real decision-making setting would use the framework, and who participates?
- Which rules transfer beyond the game, and which depend on its incentives or fictional authority?
- What accountability, membership, and decision-history requirements arise in that setting?
- What evidence would justify maintaining a separate framework?
